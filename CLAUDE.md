# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`microman` (module `github.com/byte-cats/microman`) is a minimal Go HTTP API starter kit built without a web framework — just `net/http`, `gorilla/mux` for routing, and `urfave/negroni` for JWT middleware. It's a scaffold/example project ("Minimal Go Api Starter Kit"), not a production service — several REST handlers are still stubs.

## Commands

- Build the actual entrypoint (matches what CI runs): `go build ./cmd/microguy/main.go`
- Build everything: `go build ./...`
- Test: `go test ./...`
- Vet: `go vet ./...`
- Format check: `gofmt -l .`
- Tidy modules: `go mod tidy` (there is no `vendor/` directory — it was removed; plain module-mode builds)
- Regenerate Swagger/OpenAPI docs after changing handler doc comments or `cmd/microguy/main.go`'s API annotations: `swag init` from the repo root (writes `docs/docs.go`, `docs/swagger.json`, `docs/swagger.yaml` — don't hand-edit those, they're generated)
- Run a single test: `go test ./<package> -run TestName -v`
- There is no Makefile, despite `Jenkinsfile` invoking `make unit-tests` / `make functional-tests` and `deploy/build.sh` assuming a `make`-based flow — those CI/build scripts are stale relative to the actual repo layout.
- `deploy/build.sh` and the `Dockerfile` both build from `cmd/microbro/`, but the real (only) command package is `cmd/microguy/` — a stale-path leftover from a rename. Follow `.github/workflows/go.yml` (which builds `cmd/microguy`) as the source of truth for what actually builds.

## Architecture

Call chain: `cmd/microguy/main.go` → `app` package → `server` package → `handlers` package, with `auth`, `data`, and `log` as supporting packages. Every package has its own `README.md` (or `auth/auth.md`) with more detail — check those first when working in a given directory.

- **`app/`** — `Api` struct is the top-level container: holds `Settings` (title/hostname/port/version, populated from env vars with defaults) and `server.Served` (router + an unused raw `http.ServeMux`). `app.DefaultAPIClient()` builds the default instance; `app.RunDefaultClient()` calls `http.ListenAndServe`.
- **`server/`** — `InitRouter()` creates the `*mux.Router`; `InitRoutes()` registers every endpoint in one place — check it first to see the full route surface. General endpoints go straight to `handlers.*`, `/swagger/*` is mounted via `docs.RegisterSwaggerRoute`, and all `/auth/*` routes are mounted via `auth.AuthRoute`.
- **`handlers/`** — one file per general route (`home.go`, `info.go`, `redirect.go`, `docs.go`, `health.go`) plus CRUD stubs (`add.go`, `get.go`, `edit.go`, `delete.go` — these still just write fixed strings, not real database-backed logic). `respond.go` has the shared `writeString` helper. Handler doc comments (`@Summary`, `@Router`, ...) feed `swag init`. Auth routes live in the `auth` package, not here — there's no `handlers/auth.go`.
- **`auth/`** — owns all authentication logic end-to-end and is mounted directly via `auth.AuthRoute(router)`, not adapted through `handlers/`. JWT issuing/verification (`jwt.go`, `golang-jwt/jwt/v5`), a negroni-based `JWTMiddleware` (`middleware.go`) that verifies the bearer token and stashes claims on the request context, credential validation (`rules.go`), bcrypt hashing (`password.go`), a `User` model (`users.go`), secrets from env (`secrets.go`), AES encrypt/decrypt (`crypto.go`), and MySQL access (`database.go`). `route.go`'s `AuthRoute` mounts `POST /auth/login` (public, real), `GET /auth/me` (JWT-protected, real — the live demonstration the middleware actually gates something), and `POST /auth/user/new` / `POST /auth/user/remove` (honest `501 Not Implemented` — no create/remove-user logic exists yet, so these don't pretend to work).
- **`data/`** — `connection.go`'s `Connect()`/`Close()` open/close a MySQL connection through [`byte-cats/datastation`](https://github.com/byte-cats/datastation) (`DATABASE_TYPE`/`HOST`/`PORT`/`NAME`/`USER`/`PASSWORD` env vars, MySQL-only today since that's the only engine datastation's connect helper fully supports). `json.go`'s `JsonConvert` wraps `json-iterator/go` (drop-in `encoding/json` replacement for speed). `data.go` is still a placeholder for future data structures.
- **`log/`** — custom logger (`log.Log`), unrelated to the stdlib `log` package also used directly in a few handlers (sometimes under an alias, e.g. `log2`, in the same file).
- **`docs/`** — Swagger/OpenAPI. `swag.go` exposes `RegisterSwaggerRoute`; `docs.go`/`swagger.json`/`swagger.yaml` are generated by `swag init`, sourced from doc comments in `handlers/*.go` and package-level annotations in `cmd/microguy/main.go`.

## Known repo-wide gotchas

- Module path is lowercase (`github.com/byte-cats/microman`) while the GitHub org/repo is `Byte-Cats/microman` — matters for import paths vs. browser URLs.
- `deploy/build.sh` and `Dockerfile` reference the stale `cmd/microbro` path (see Commands above).
- Test coverage exists but isn't exhaustive: `app` (settings env-var fallback), `auth` (credential-rule validators), and `data` (`JsonConvert`) have table-driven tests; DB-dependent code and most handler boilerplate don't.
